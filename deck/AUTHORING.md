# スライドの書き手への規則（ケーススタディ）

ケーススタディ「データ指向で設計する大規模クラウドサービス ― ケーススタディ（実測）」の 1 Part を `deck/pNN.js` として書く。読者は新任のテックリーダー。ガイド（`data-intensive-design-guide`、256 枚）を読んだ人が、「その主張は実機でどうだったか」を確かめるための資料。

## 1. Part の構成

| ファイル | Part | 中身 | 枚数の目安（扉を含む） |
| --- | --- | --- | --- |
| `p00.js` | Part 0 この資料の読み方 | 表紙、結論の先出し、架空の宅配注文サービス、測り方（N・B・BE、除去実験、正常な操作、判定器の監査、2 回の実行）、共通の基準 B1〜B6、環境と版 | 12〜14 |
| `p01.js` | Part 1 題材 A：基盤をまたぐデータ統合 | `results/a/summary.md` | 15〜18 |
| `p02.js` | Part 2 題材 B：置換と更新の演習 | `results/b/summary.md` | 18〜22 |
| `p03.js` | Part 3 題材 C：ログ・分析の費用と性能 | `results/c/summary.md` | 18〜22 |
| `p04.js` | Part 4 題材 D：整合性の異常の再現 | `results/d/summary.md` | 14〜17 |
| `p05.js` | Part 5 まとめ | 2 回の実行で変わったこと（`results/RERUN.md`）、ガイドと食い違った点・足す点、限界と未検証、設計レビューに持ち帰ること | 12〜14 |

題材の Part の型：扉（問いと、結論の先出し）→ 何を比べたか（構成 N・B・BE と世界の図）→ ケースの一覧（障害と正常な操作）→ 構成 × ケースの結果 → 除去実験（その要素が何を防いだか）→ 測定値 → ガイドの記述との照合（一致／食い違い／実行によって変わった／未検証）→ 期待どおりにならなかったこと・原因を調べていないこと → 限界 → 設計レビューに持ち帰ること。

## 2. 数字の規則（最重要）

- **スライドの数字は、必ず `results/<題材>/summary.md` と `results/RERUN.md` から写す。** 記憶や計算で作らない。summary に無い数字が要るときは、`results/<題材>/*.jsonl`（2 回目）と `results/<題材>/run1/*.jsonl`（1 回目）から数え、数え方を `research/reviews/verify_pNN.md` に書く
- 実験は 2 回、最初から流した。**2 回で「起きた／起きなかった」や大小が変わった結果は、2 回の値を並べて書き、断定しない**（summary の「1 回目 a・2 回目 b」「実行によって変わった」をそのまま反映する）。2 回とも同じだった結果だけを、1 つの値で書いてよい
- 並行の競合に頼る件数は「合計（起きた試行／試行）」の形で書く。時間は p50・p95・回数と、同じ環境の中の相対比較であることを書く。**絶対値を一般化しない。製品の優劣を断定しない**（どの形の問い合わせで、どちらに差が出たか、を書く）
- 「0 件」は「この手順と試行回数で起きなかった」という意味。「防げる」「起きない」と書かない
- 測っていないことは「未検証」。原因を調べていないことは「原因は調べていない」（推定は推定と書く）
- 期待どおりにならなかった結果、ガイドと食い違った結果を、隠さず 1 枚以上使って書く
- summary より強く言わない。summary の判定が「一部だけ再現」なら、スライドも一部だけ再現

## 3. 使ってよい道具

ガイドと同じ `lib.js`（pptxgenjs を直接呼ばない。例外は単純な図形）。書き方の実例は、ガイドのリポジトリの `deck/p06.js`・`p09.js`・`p15.js` を読む（中身は写さない。道具の使い方だけ見る）。

```js
module.exports = (L) => {
  const { C, SH, HEX } = L;
  L.section('Part 1 題材 A：基盤をまたぐデータ統合');
  L.divider('PART 1', '題', '副題（結論）', ['問い', …], 'ノート');
  {
    const s = L.content('タイトル（結論の文）', { lead: 'リード 1 文', stages: [3], tag: '題材 A', notes: '…', refs: { spec: '…', inst: '…', book: '…' } });
    L.table(s, [[見出し…], [行…]], { x: 0.6, y: 1.95, w: 12.1, colW: [..], fontSize: 11.5, rowH: 0.5 });
  }
};
```

- `L.content(title, {lead, stages, tag, notes, refs})`、`L.divider`、`L.table`、`L.card`、`L.note(s, kind, text, {x,y,w,h,size,label})`（kind：leader・warn・tip・add・decide）、`L.bullets`、`L.T`、`L.flow`、`L.box`、`L.arrow`、`L.stat`、`L.bar`、`L.code`
- アイコンは react-icons の `Md…` 名（実在するものだけ。例：MdStorage、MdSync、MdWarning、MdFlag、MdSchema、MdHub、MdTimeline、MdSecurity、MdLightbulb、MdCompareArrows、MdAccountTree、MdCloud、MdLock、MdSpeed、MdBugReport、MdChecklist、MdInsights、MdHistory、MdSwapHoriz、MdDeleteForever、MdBackup、MdRule、MdScience）
- `stages`：ガイドの 9 つのステップのパンくず（0 要件、1 所有、2 モデル、3 流れ、4 契約、5 複製、6 正しさ、7 導出、8 基盤）。その実験が確かめるステップを点灯する
- `tag`：`'題材 A'` など。Part 0 と 5 は `'読み方'`・`'まとめ'`

### 配置（単位はインチ。スライドは 13.333 × 7.5）

- 本文の領域：x 0.6〜12.7（幅 12.1）、y 1.95〜6.5（lead があるとき）。lead が無ければ y 1.4 から。**y + h は 6.5 を超えない**
- 表：`rowH × 行数 + y ≤ 6.4`。表の下に注記を置くなら 0.15 以上あける。**表と他の図形を重ねない**
- 文字：本文 12.5〜14、表 10.5〜12、最小 10.5。1 枚の文字は 350 字程度まで（表を除く）。表は 1 枚 8 行・6 列程度まで。summary の大きな表は、要点の行と列だけに絞る（全部は summary にある、と根拠の行で示す）
- **タイトルは結論の文**（34 字以内）。1 枚 1 メッセージ

## 4. 根拠の行（全スライド必須）

`refs: { spec, inst, book }` のうち 1〜3 個。1 個 60 字程度まで。この資料ではラベルが次の意味になる。

- `spec`（表示は「結果」）：結果のファイルと節。例：`results/a/summary.md「障害のケース」。main.jsonl 147 実行 × 2 回`
- `inst`（表示は「ガイド」）：ガイドの該当 Part とスライドの題。例：`ガイド Part 6「二重書き込みの不整合は 2 つの型で起きる」`
- `book`（表示は「文書」）：製品の公式文書（版と確認月）。使うのは、ガイドや summary が既に引いている文書だけ。新しい事実を文書から足さない

## 5. 言葉

- 訳語はガイドに揃える：記録のシステム、導出データ、逐次更新、ロストアップデート、ライトスキュー、クォーラム、チェンジデータキャプチャ（CDC）
- 構成の呼び名：N（素朴な構成）、B（共通の基準を入れた構成）、BE（基準＋題材ごとの重点）。初出の Part で 1 行で説明する
- 平易な日本語。1 文は短く。煽らない。会社・サービス・数値は架空で、実在の組織とは関係がないことを Part 0 に書く
- 手元のパス（ドライブ名・ホームから始まるパス）を書かない

## 6. 発表者ノート（全スライド必須）

読むだけで発表できる量（250〜450 字）。数字の条件（試行の数、並行度、2 回のどちらか）、但し書き、次のスライドへのつなぎ。「です・ます」体。

## 7. 確認

```bash
cd deck
export NODE_PATH="<pptxgenjs などを入れた node_modules のパス>"
node build_one.js pNN      # qa/pNN.pptx ができ、枚数・refs 漏れ・ノート漏れ・長い題が出る
```

`without refs: 0 without notes: 0`、長い題の警告なし、になるまで直す。**PowerPoint は起動しない**（見た目の検査は取りまとめ役が行う）。書くファイルは `deck/pNN.js` と `research/reviews/verify_pNN.md` だけ。

`research/reviews/verify_pNN.md` には、スライドに載せた数字を全部、表で残す：`スライドの題｜数字・主張｜出どころ（summary の節、または jsonl と数え方）｜1 回目｜2 回目｜結果（一致／直した）`。
